# Manual Payment Implementation Plan (TASKS.md section 19)

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an Owner or Admin record a Manual Payment (Cash, Check, Other) against a Sent or Viewed Invoice from the mobile invoice detail screen, transitioning it to Paid.

**Architecture:** One new public Convex mutation in `packages/backend/convex/payments.ts` that mirrors the existing `fulfillCheckout` write pattern (patch invoice, insert `paymentRecords`, insert `logs`). One new mobile bottom sheet component (modeled on `send-confirmation.tsx`) wired into `invoice-detail.tsx`. No schema changes.

**Tech Stack:** Convex, `@repo/types` enums, `@repo/utils` permission/status helpers, React Native + existing `BottomSheet` / `FormSegment` / `FormField` / `FormButton` components.

### Task 3: `recordManualPayment` mutation

**Files:**
- Modify: `packages/backend/convex/payments.ts`

- [ ] **Step 1: Add imports**

```ts
import { ConvexError, v } from "convex/values";
import { internalMutation, internalQuery, mutation } from "./_generated/server";
import { canAcceptPayment, canRecordManualPayment, isValidStatusTransition } from "@repo/utils";
import { requireOrgMember } from "./lib/auth";
import { manualPaymentMethodValidator } from "./lib/validators";
```

- [ ] **Step 2: Add mutation (append to file)**

```ts
export const recordManualPayment = mutation({
  args: {
    invoiceId: v.id("invoices"),
    method: manualPaymentMethodValidator,
    reference: v.optional(v.string()),
  },
  handler: async (ctx, args) => {
    const invoice = await ctx.db.get(args.invoiceId);
    if (!invoice) throw new ConvexError({ code: "NOT_FOUND", message: "Invoice not found." });

    const { user, membership } = await requireOrgMember(ctx, invoice.orgId);
    if (!canRecordManualPayment(membership.role)) {
      throw new ConvexError({ code: "FORBIDDEN", message: "You do not have permission to record payments." });
    }

    if (!isValidStatusTransition(invoice.status, InvoiceStatus.PAID)) {
      throw new ConvexError({ code: "VALIDATION_ERROR", message: "Only sent or viewed invoices can be marked paid." });
    }

    const now = Date.now();
    const reference = args.reference?.trim() || undefined;

    await ctx.db.patch(invoice._id, { status: InvoiceStatus.PAID, paidAt: now, updatedAt: now });
    await ctx.db.insert("paymentRecords", {
      invoiceId: invoice._id,
      method: args.method,
      amount: invoice.total,
      reference,
      paidAt: now,
      paidBy: user._id as string,
    });

    const metadata = { method: args.method, reference, amount: invoice.total };
    await Promise.all([
      ctx.db.insert("logs", {
        eventType: LogEventType.INVOICE_PAID,
        actorId: user._id as string,
        orgId: invoice.orgId as string,
        entityType: "invoice",
        entityId: invoice._id as string,
        metadata,
        createdAt: now,
      }),
      ctx.db.insert("logs", {
        eventType: LogEventType.PAYMENT_MANUAL_RECORDED,
        actorId: user._id as string,
        orgId: invoice.orgId as string,
        entityType: "invoice",
        entityId: invoice._id as string,
        metadata,
        createdAt: now,
      }),
    ]);
  },
});
```

Notes:
- `amount` is always the invoice `total`. Partial payments are out of scope (Paid is terminal, no balance tracking).
- `paidBy` stores the internal user id, paralleling `STRIPE_PAID_BY` for Stripe.
- Two log rows mirror `fulfillCheckout` (INVOICE_PAID for invoice timeline, PAYMENT_* for payment audit).
- Check the exact shape of `actorId` in the `logs` table validator in `schema.ts` before writing; `fulfillCheckout` omits it because there is no actor.

## Assumptions

| # | Assumption | If wrong |
|---|-----------|----------|
| A1 | Manual payment always records the full invoice `total`. No partial payments. | Would need balance tracking and a non-terminal partial state; out of V1 scope. |
| A2 | UI does not hide the button by role; server enforces Owner/Admin and a Member sees an Alert on failure (same as the existing send flow, which also has no client-side role gate). | Add role to `useCurrentOrg` and gate the button. Small follow-up, not blocking. |
| A3 | `notes` from `manualPaymentSchema` (`@repo/utils`) is not persisted; `paymentRecords` has no `notes` column and the TASKS.md spec only names "reference". | Add `notes: v.optional(v.string())` to the schema. Avoided to keep schema untouched. |
| A4 | No payment receipt email is sent on manual payment. That belongs to 25.2 ("Send payment receipt after payment success"), which is also not wired for Stripe yet. | Schedule the email action from the mutation when 25.2 lands. |
| A5 | `logs.actorId` is optional `string` in schema (the `fulfillCheckout` call omits it). | Adjust the insert shape. |

## Risks

- **Irreversible action.** Paid is terminal; there is no "unmark". The sheet states this explicitly. Accepted per the status machine.
- **Race with Stripe checkout.** A client could complete Checkout while the org marks it paid manually. `fulfillCheckout` already handles `status === PAID` by logging "already paid" and returning `already-paid`; the Stripe charge still occurs. Refund handling is an Admin Panel concern (section 30). Flagging, not solving here.
- **`FormField` API unknown.** Props in the plan are a guess; confirm against `form-field.tsx` during Task 4.

## Acceptance criteria

1. Owner or Admin can open a Sent or Viewed invoice in the mobile app, tap "Mark as Paid", pick Cash/Check/Other, optionally enter a reference, confirm, and see the invoice badge change to Paid with a Paid date.
2. A `paymentRecords` row exists with `method` in {CASH, CHECK, OTHER}, `amount === invoice.total`, `paidBy` = acting user id, `reference` set when provided.
3. Two `logs` rows exist: `INVOICE_PAID` and `PAYMENT_MANUAL_RECORDED`, both with `actorId` and `orgId`.
4. A Member calling the mutation receives `FORBIDDEN`.
5. Calling on a Draft, Paid, or Void invoice receives `VALIDATION_ERROR`; no writes occur.
6. The "Mark as Paid" button is not rendered for Draft, Paid, or Void invoices.
7. `pnpm typecheck` and `pnpm lint` pass.
