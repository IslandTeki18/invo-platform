# Plan: Run the mobile app in Expo Go

Status: executed 2026-08-20. See "Execution notes" at the end.

## Purpose

`apps/mobile` currently fails to bundle, so it cannot run in Expo Go at all. This plan fixes the
bundling blocker and the dependency-state issues that would crash the app in the Expo Go runtime,
with no changes to app features.

## Findings (verified)

| # | Finding | Evidence | Impact in Expo Go |
|---|---------|----------|-------------------|
| 1 | Metro cannot resolve `../../../../../convex/_generated/api` | `npx expo export --platform ios` fails with "Unable to resolve module". Expo derives `watchFolders` from `pnpm-workspace.yaml` globs (`apps/*`, `packages/*`); root `convex/` is outside them. | Hard blocker. Bundle never loads. |
| 2 | Stale nested install in `apps/mobile/node_modules` + `apps/mobile/package-lock.json` (npm run inside the app; both untracked) | `expo-doctor` reports duplicate `expo`, `react`, `react-native`, `expo-constants`, etc. between `apps/mobile/node_modules` and root `node_modules`. | Two React / RN copies -> "Invalid hook call" or module registry errors at runtime. |
| 3 | Two React versions: mobile pins `react@19.2.0`, `@clerk/clerk-react` peer requires `~19.2.3+`, so pnpm nested `react@19.2.4` under `@clerk/clerk-react` | `node_modules/@clerk/clerk-react/node_modules/react` = 19.2.4. admin/marketing already use `^19.2.4`. | Clerk provider renders with a second React -> hook errors. |
| 4 | Native-module version drift vs. the Expo Go SDK 55 binary | `npx expo install --check`: `react-native-worklets` 0.7.2 vs 0.7.4, `@react-native-async-storage/async-storage` 3.0.1 vs 2.2.0, `@react-native-community/datetimepicker` 9.1.0 vs 8.6.0, RN 0.83.2 vs 0.83.10, plus 14 `expo-*` patch bumps. | Expo Go ships fixed native versions. JS/native mismatch on worklets and async-storage is a known startup crash. |
| 5 | No `apps/mobile/.env.local` | Only `.env.example` exists. `_layout.tsx` does `new ConvexReactClient(process.env.EXPO_PUBLIC_CONVEX_URL!)` at module load. | Throws on first render. Local setup step, not a code change. |

Non-issues (checked, no change needed): `expo-secure-store`, `expo-symbols`, `expo-glass-effect` are
bundled in Expo Go SDK 55; `@repo/*` resolve via `packages/*` watch folders + tsconfig paths;
`.css` / `.module.css` imports are shimmed by Expo Metro on native; `@clerk/clerk-expo` supports
Expo Go; no `expo-dev-client` or other dev-build-only module is installed.

## Steps

### Step 1: Add root `convex/` to Metro watch folders

- Create `apps/mobile/metro.config.js`:
  - `getDefaultConfig(__dirname)` from `expo/metro-config`
  - `config.watchFolders = [...config.watchFolders, path.resolve(__dirname, '../../convex')]`
  - export config
- Nothing else in the config. `nodeModulesPaths` and the workspace globs already resolve correctly.

### Step 2: Remove the stale nested npm install

- Delete `apps/mobile/node_modules` and `apps/mobile/package-lock.json` (both git-ignored, untracked).
- Delete root `package-lock.json` (git-ignored, untracked) so `expo-doctor` stops flagging multiple lock files.
- No tracked files change in this step.

### Step 3: Align React with Clerk's peer range

- `apps/mobile/package.json`: `react` and `react-dom` from `19.2.0` to `19.2.4` (exact pin, matching
  the existing style in this file). Matches admin/marketing and removes the nested copy under
  `@clerk/clerk-react`.

### Step 4: Align native module versions with Expo Go SDK 55

- From `apps/mobile`, run `npx expo install --fix`. Expected changes to `apps/mobile/package.json`:
  - `react-native` 0.83.2 -> 0.83.10
  - `react-native-worklets` 0.7.2 -> 0.7.4
  - `@react-native-async-storage/async-storage` ^3.0.1 -> 2.2.0
  - `@react-native-community/datetimepicker` ^9.1.0 -> 8.6.0
  - `expo` and 13 `expo-*` packages to their current SDK 55 patch ranges
- Run `pnpm install` from the repo root; `pnpm-lock.yaml` updates.
- `react-native-reanimated` 4.2.1 is not flagged; leave it.

### Step 5: Local env (no code change)

- `cp apps/mobile/.env.example apps/mobile/.env.local` and fill `EXPO_PUBLIC_CONVEX_URL` and
  `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`. Documented only; not committed.

## Assumptions

- Target is Expo Go for SDK 55 on a physical device or simulator; no dev build (`expo-dev-client`) is wanted.
- The user has a Convex deployment URL and a Clerk publishable key available for `.env.local`.
- The async-storage 3.x -> 2.2.0 and datetimepicker 9.x -> 8.6.0 downgrades are acceptable. Neither
  package's newer API is used in `src/` beyond `DateTimePicker` default props, which are unchanged
  across those majors. Flagged below as a risk regardless.
- `pnpm install` is the only sanctioned install path; `npm install` inside `apps/mobile` was accidental.

## Acceptance criteria

1. `npx expo export --platform ios` and `--platform android` from `apps/mobile` complete with no resolution errors.
2. `npx expo-doctor` reports no duplicate native module dependencies and no multiple-lock-file warning.
3. `npx expo install --check` reports no outdated packages.
4. Only one `react` and one `react-native` exist under `node_modules` (no nested copy under `@clerk/clerk-react`).
5. `pnpm dev:mobile` starts Metro; scanning the QR code in Expo Go loads the app to the root layout without a red screen.
6. `pnpm typecheck` and `pnpm lint` pass for the mobile package.

## Execution notes

Deviations from the plan, all required to reach the acceptance criteria:

- `packages/utils/src/token.ts` and `slug.ts` imported Node `crypto`; Metro cannot bundle that for
  native. Both now use Web Crypto (`generateAccessToken` delegates to `generateAccessTokenWeb`).
  Neither function had production callers. 120/120 utils tests still pass.
- `expo install --fix` reset `react` to 19.2.0 (Expo's SDK 55 pin). Kept 19.2.4 for Clerk's peer
  range and added `expo.install.exclude: ["react", "react-dom"]` to `apps/mobile/package.json`.
- pnpm auto-resolved the `@expo/metro-runtime` peer to 55.0.6; `expo-router` requires `^55.0.12`.
  Added `@expo/metro-runtime ~55.0.12` as an explicit dependency.
- `expo install --fix` added config plugins (`datetimepicker`, `expo-image`, `expo-secure-store`,
  `expo-web-browser`) to `app.json`. Harmless in Expo Go; kept.
- `pnpm typecheck` (4 errors) and `pnpm lint` (3 errors) fail identically on the pre-change tree;
  pre-existing, out of scope.

Results: `expo-doctor` 20/20, `expo install --check` clean, single `react` copy, iOS and Android
`expo export` succeed. V4 (device run in Expo Go) not performed from this environment.

## Follow-up: SDK 54 downgrade (2026-08-20)

The App Store's latest Expo Go is 54.0.2 (SDK 54, released 2025-09-23). No Expo Go build exists
for SDK 55+ on physical iPhones, so the project was moved to SDK 54 (user chose this over a dev build).

- `npx expo install expo@^54` + `--fix`: RN 0.81.5, React 19.1.9, reanimated 4.1.7, worklets 0.5.1,
  all `expo-*` to SDK 54 ranges. `expo-auth-session` pinned explicitly so Clerk's transitive copy
  matches the SDK.
- `apps/admin`, `apps/marketing`: React `^19.2.4` -> `~19.1.9`. Required because the single hoisted
  `@clerk/clerk-react` otherwise carried a nested React 19.2.4 that the mobile bundle would load
  alongside 19.1.9. Web apps typecheck clean on 19.1.
- SDK 54 API differences fixed in mobile source:
  - `NativeTabs.Trigger.Label/Icon` -> `Label`/`Icon` imports; `renderingMode` prop removed (`(tabs)/_layout.tsx`).
  - `SymbolView name` takes a string, not a per-platform object (`collapsible.tsx`).
  - `useColorScheme` returns `null`/`undefined`, not `'unspecified'` (`use-theme.ts`).
  - `StyleSheet.absoluteFillObject` kept (removed only in RN 0.86).
- `app.json` plugins: removed `expo-image` and `expo-status-bar` entries that `expo install --fix`
  added; those packages have no config plugin in SDK 54.
- `apps/mobile/metro.config.js` deleted: `convex/` moved to `packages/backend` (separate change),
  which Expo already watches via `packages/*`.

Remaining `expo-doctor` warning: duplicate React 19.2.4 under `@react-pdf/*`. Those are
`packages/backend` (Convex action) dependencies and are never bundled into the mobile app.

### Runtime fixes after first successful load in Expo Go 54

- `@react-navigation/native` must be >= 7.3.17 to match the `native-stack` that `expo-router` 6
  resolves (`createScreenFactory`). Expo's specifiers (`^7.1.8`, `^7.4.0`) are kept; pnpm resolves
  the carets to current versions.
- RN 0.81's renderer is pinned to React 19.1.0 exactly. Root `pnpm.overrides` forces `react` and
  `react-dom` to 19.1.0 repo-wide; without it Clerk's peer range (`~19.1.4`) made pnpm nest a second
  React. All three apps pin 19.1.0. Clerk logs a peer warning only.
- Hermes on RN 0.81 has no global `crypto`; `use-invoice-form.ts` uses `randomUUID` from
  `expo-crypto` (added as a direct dependency).

Verified on device: app loads in Expo Go 54.0.2 via `npx expo start --clear --tunnel`.
